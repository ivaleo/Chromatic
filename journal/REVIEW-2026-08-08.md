### 2.3 Три формализма — фактически один класс

Сопоставление определений показывает, что «зоопарк» избыточен:

- **power_coloring**: узлы t₁…t_k с весами, решётка периодов Γ, цвет = номер
  узла. **semilattice**: P = ⋃(Γ+tᵢ), ячейки P (Вороного/лагерровы), цвет =
  орбита узла. Это **буквально один и тот же класс** — журнал 08.08 сам это
  фиксирует в атрибуции. Различие только в акценте (свобода весов vs
  арифметика индексов) и в инструментах (Вульф-оценщик vs точный 2D-сертификатор).
- **МСВ** (msv_core): то же множество узлов, но у каждой орбиты своя
  подрешётка Γᵢ ⊆ P периодов, цвет = (i, класс mod Γᵢ). Это **строгое
  обобщение** первых двух (они — случай Γᵢ = Γ, jᵢ = 1) и одновременно
  обобщение решёточной схемы (s=1 — ровно схема Иванова).

Итого класс один: *Γ-периодическая лагеррова мозаика + правило раскраски
узлов, инвариантное относительно подрешётки на каждой орбите*. Все три
реализации, четыре названия («степенные/мозаичные», «полурешётчатые»,
«кластерные», «псевдо-решётки/МСВ») и три верификатора описывают его срезы.
Рекомендация — §4.3.

## 4. Упрощение методов

### 4.1 Лемма P1 — частный случай теоремы о бюджете слоя

`lem:P1` (diam ≤ √(diam₀²+t²)) — это `prop:layerbudget` при L = tℤ
(R_L = t/2). Сейчас они доказываются независимо в двух разделах, и связь
упомянута лишь ремаркой («два способа потратить один бюджет»). Предлагаемая
подача: определить ламинирование сразу слоевой решёткой L ранга m ≥ 1
(поправки cₖ, склейка), доказать бюджет один раз, а прямую tℤ и шестиугольник
A₂ получить как случаи. Это склеивает §7 (dim9-12) и §8 (product) в один
механизм и убирает дубль.

### 4.2 «Ширина как ресурс» — единый стержень, который стоит проговорить

Три центральных факта — одно исчисление: Σ1/dᵢ² ≤ 1 (произведение),
R_L ≤ (diam₀/2)√(d₀²−1) (слой), d = 2/ρ и √(7/3)/ρ (α-лестница). Сейчас
читатель собирает эту картину из трёх разделов. Один абзац-манифест в начале
§product («ширина — расходуемый ресурс; вот три способа его тратить») плюс
согласованные ссылки сильно упростят чтение, ничего не меняя в математике.

### 4.3 Один нерешёточный формализм вместо трёх

По §2.3: дать одно определение (Γ-периодическая лагеррова мозаика + пер-орбитные
Γᵢ), из него вывести три частных случая, выбрать одно имя (естественный
кандидат — «мозаичные раскраски», с «полурешётчатыми» как термином для
подкласса с акцентом на арифметическую квантизацию; «псевдо-решётки» и
«кластерные» — убрать из будущих текстов, оставив в архивных README пометку о
соответствии). Выгоды: §10 + полурешётчатая линия становятся одним разделом с
одной логикой «класс → полы → где не окупается (нормы) → где окупается
(не-нормы)»; исчезает необходимость трижды доказывать «содержит схему Иванова
как частный случай» (сейчас это `prop:contains`, §1 журнала 08.08 и README
МСВ — три раза).

### 4.4 Каталог полов — один раздел и один модуль

Полы/экраны размазаны: объёмный Минковского (`dim9-12.tex` §7.1,
`core/minkowski.py`), инрадиусный (`product.tex` §8.4, `minkowski.py`),
упаковочный (`tilings.tex` §10.5, `paradigm_floor.py: index_window`), пол 2ⁿ
(§10.2, `paradigm_floor.py`), учёт k=F/δ_C (§10.4), окно КЛ (§10.6). Дубли в
коде: `semilattice.plane_floor` ≡ инрадиусный экран (признано в докстринге),
`semilattice.absolute_floor` ≡ обобщение thm:floor. Предложение: в статье —
единый раздел «Полы метода» с таблицей «какой пол на чём стоит и что
запрещает»; в коде — один `core/floors.py` с единым API (инварианты → нижняя
граница k), остальное — тонкие обёртки. Это одновременно и главный «продукт
для сообщества»: каталог полов — то, чем будут пользоваться продолжатели.

### 4.5 Сертификаторы диаметра слоёных решёток

Три модуля (`piecewise_covrad.py` — два слоя, `layer_certificate.py` —
гекс-полосы с редукцией к двухслойной задаче, `layered_covrad.py`) с разными
интерфейсами. Свести к одному модулю с двумя режимами (слой ранга 1 / ранга 2)
и одной точкой калибровки (12005), задокументировав, какой режим для какой
конструкции. Это прямо снизит порог входа для «сертификации 21609».
