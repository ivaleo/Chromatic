# runs/ — сырые выгрузки кампаний

Здесь лежат результаты прогонов, на которые не опираются ни статья, ни тесты:
разведочные запуски, промежуточные стадии, перебор параметров. README
(особенно `README-dim5-9.md`) ссылаются на них по именам как на след работы.
Они сохранены как воспроизводимый след работы, а не как опорные данные.

- формат: тот же json, что и раньше, сжатый gzip (`*.json.gz`, около ×13);
- чтение из кода: `chromatic_research.paths.load_json("<имя>.json")` —
  распаковывает прозрачно, имя указывается без `.gz`;
- чтение из оболочки: `gzcat audit-data/runs/<имя>.json.gz | jq .`;
- опорные данные (те, на которые ссылаются статья, доки, тесты) — в `../results/`.

Кампании, чей вывод никто не читает (разведка, `*_best`, `e7_best_C.npy`),
пишут сюда через `runs_path()` несжатыми; перед коммитом такой файл сжимают:
`gzip -9 audit-data/runs/X.json`. Опорные артефакты по-прежнему пишутся в
`results/` через `results_path()`.

Если файл отсюда понадобился статье или тесту — перенесите его в `results/`
разжатым:

```bash
gzcat audit-data/runs/X.json.gz > audit-data/results/X.json
git rm audit-data/runs/X.json.gz
```

На 16.09.2026 здесь 542 файла, 11 МБ в сжатом виде. В тот день сюда перенесены
шесть крупных архивов отрицательных экранов из `results/` (`highs_kernel_*`,
`discrete_highs_d6_336_cycle2_archive`, `lazy_prime_a9_*`, `lazy_cxx_a9_17150`):
на них ссылаются только README и журнал, имена прежние.

**Общие профили.** В прогонах `group_transversal_d6_336_p{11,13,17}_*` поле
`profiles` совпадало у разных запусков и хранится один раз — в файле
`*_profile.json.gz` или `*_profile_l3.json.gz`. Остальные файлы вместо него
несут `profiles_ref` с именем этого файла:

```python
run = load_json(name)
if "profiles_ref" in run:
    run["profiles"] = load_json(run["profiles_ref"])["profiles"]
```
